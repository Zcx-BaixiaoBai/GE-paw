### 2.2 测试层级划分

| 层级 | 目录 | 数量 | 目的 | 触发频率 |
| --- | --- | --- | --- | --- |
| **Unit** | `tests/unit/` | 2 828 | 验证单文件 / 单函数行为，使用大量 mock，无 IO | 每次 push / PR |
| **Contract** | `tests/contract/` | 243 | 验证渠道、provider、guardian 等多实现接口的一致性 | 每次 push / PR |
| **Integration** | `tests/integration/` | 167 | 验证多模块协作（FastAPI + DB + Settings + 路由） | PR 跑 `p0`，push/merge 跑 `p0+p1`，nightly 跑全集 `p0+p1+p2` |
| **E2E** | `e2e/` | — | Playwright 浏览器流（不在 pytest 范围） | `e2e-smoke.yml` / `e2e-integration.yml` 单独工作流 |

### 2.3 关键配置

`pyproject.toml`：

```toml
[tool.pytest.ini_options]
asyncio_mode = "auto"
testpaths = ["tests"]
```

`tests/conftest.py`（核心 918 行）提供：
- 第三方缺失库 mock（`aibot`、`lark_oapi`）
- 临时目录 / 文件 fixtures
- 数据库 session 隔离
- 全局 env 覆盖

`tests/integration/conftest.py`（15K 行）提供 FastAPI `TestClient`、带覆盖子进程的 settings、workspace 等。

### 2.4 标记（marker）系统

集成测试用 `@pytest.mark.integration` + `@pytest.mark.p0/p1/p2` 三档划分，CI 中按事件分级执行：

| 事件 | 跑哪一档 |
| --- | --- |
| `pull_request` | `integration and p0` |
| `push`（main/master/dev/develop） | `integration and (p0 or p1)` |
| nightly（`full-tests-nightly.yml`） | `integration`（全档） |

### 3.3 跳过用例

unit 16 个 + contract 2 个，主要是：
- 缺少可选依赖（如 `aibot`、`lark_oapi` 被全局 mock）
- 平台特定（macOS / Linux 专用）
- 需要真实凭据的渠道（feishu / dingtalk 签名 path）

### 3.4 警告统计

| 类别 | 出现次数 | 说明 |
| --- | ---: | --- |
| `PytestUnknownMarkWarning`（`p0/p1/p2`） | ~330 | 集成测试用 marker 未在 `pyproject.toml` 注册；不影响测试结果 |
| `PytestWarning`（asyncio 标错） | 12+ | `telegram/wechat/xiaoyi` 等部分 sync 测试误打 `@pytest.mark.asyncio`；功能正确 |
| `DeprecationWarning`（`audioop`） | 多次 | Python 3.13 准备弃用 `audioop`；SIP 渠道用 |
| `LegacyAPIWarning`（SQLAlchemy 1.x `Query.get`） | 多次 | wiki pipeline 测试用旧 API |
| `RuntimeWarning: coroutine never awaited` | 1 | telegram typing_loop 在同步测试里未 await |

**所有 warning 都不影响测试通过率**，但建议：
- 在 `pyproject.toml` 中注册 markers：
  ```toml
  [tool.pytest.ini_options]
  markers = [
    "p0: tier-0 (PR gate, fast)",
    "p1: tier-1 (pre-merge)",
    "p2: tier-2 (nightly full sweep)",
    "integration: integration test (uses FastAPI TestClient + DB)",
  ]
  ```
- 修正 12 个误打 `@pytest.mark.asyncio` 的 sync 测试。

## 6. CI / 持续集成

### 6.1 工作流一览（`/.github/workflows/`）

| 工作流 | 触发 | 作用 |
| --- | --- | --- |
| `tests.yml` | push / PR（main/master/dev） | unit + contract + integration（PR=p0，push=p0+p1），合并覆盖率报告并 PR 评论 |
| `full-tests-nightly.yml` | cron `17 18 * * *` | 完整 p0+p1+p2 扫描，含跨平台矩阵 |
| `channel-tests.yml` | 渠道变更 | 渠道相关单测 + 契约 |
| `e2e-smoke.yml` / `e2e-integration.yml` | 手动 / 定时 | Playwright 端到端 |
| `frontend-tests.yml` | web/ 变更 | 前端 |
| `pre-commit.yml` | push | black / flake8 / pylint / mypy / prettier |
| `desktop-release.yml` / `docker-release.yml` / `plugins-release.yml` / `publish-pypi.yml` | tag | 发布 |

### 6.2 矩阵策略

- OS：ubuntu-latest（必跑）+ macos-latest / windows-latest（仅 py3.10）
- Python：3.10 + 3.13
- 覆盖率只在 `ubuntu + py3.13` 收集，其他组合仅验证跨平台兼容
- `tests.yml` 受 `approval-gate` 维护者审批环境控制

### 6.3 覆盖率上传

- 单元/契约/集成各产出独立 `.coverage.*` 数据 + `coverage.*.xml`（cobertura）
- `coverage-report` job 下载并 `coverage combine` 三份，渲染 HTML + 写 `coverage_summary.md`
- PR 时通过 sticky comment 更新（marker `<!-- gepaw-coverage-summary -->`）
